## 实际修改

### 1. `feature/settings` 多账号切换 UI 与契约状态层
- `feature/settings/src/main/ets/contract/SettingsUiState.ets`：
  - 在 `SettingsUiStateOptions` 与 `SettingsUiState` 中增加多账号支持字段：
    - `availableAccounts: readonly string[]`（已配置账号的 key 列表，默认空数组）
    - `currentAccountKey: string`（当前激活账号 key，默认空字符串）
    - `showAccountSwitcher: boolean`（是否显示账号切换弹窗，默认 false）
  - 完善 `constructor`、`initial()` 与 `copyWith()`，保持参数向后兼容；
- `feature/settings/src/main/ets/contract/SettingsIntent.ets`：
  - 新增用户意图与状态回灌 Intent：
    - `SwitchAccount(accountKey: string)`：请求切换至指定账号
    - `RequestAddAccount`：请求添加新账号
    - `OpenAccountSwitcher` 与 `CloseAccountSwitcher`：打开与关闭账号切换弹窗
    - `SetAvailableAccounts(accounts: readonly string[], currentAccountKey?: string)`：装配层更新可用账号列表与当前激活账号；
  - 汇总导出至 `SettingsIntent` 联合类型；
- `feature/settings/src/main/ets/contract/SettingsEffect.ets`：
  - 新增一次性副作用描述：
    - `SwitchAccountEffect(accountKey: string)`
    - `RequestAddAccountEffect()`
  - 汇总导出至 `SettingsEffect` 联合类型；
- `feature/settings/src/main/ets/reducer/SettingsReducer.ets`：
  - 纯函数处理新增 Intent：
    - `openAccountSwitcher`：设置 `showAccountSwitcher = true`（已打开时幂等无操作）；
    - `closeAccountSwitcher`：设置 `showAccountSwitcher = false`；
    - `switchAccount`：更新 `currentAccountKey = intent.accountKey`，关闭切换弹窗，并产出 `SwitchAccountEffect(accountKey)`；
    - `requestAddAccount`：关闭切换弹窗，并产出 `RequestAddAccountEffect()`；
    - `setAvailableAccounts`：更新可用账号列表与当前激活账号 key；
- `feature/settings/src/main/ets/coordinator/SettingsCoordinator.ets`：
  - 构造器增加支持传入 `onSwitchAccount`、`onRequestAddAccount`、`currentAccountKey` 与 `availableAccounts`；
  - 在 `executeEffect` 中分发 `switchAccount` 与 `requestAddAccount` 到装配层回调；
  - 提供 `setAccounts(accounts, currentAccountKey)` 运行时动态更新方法；
- `feature/settings/src/main/ets/pages/SettingsPage.ets`：
  - 顶部 `ProfileCardView` 增加当前账号徽标展示（若存在非空 `currentAccountKey`）与快速切换入口指示器（`▾`），点击 ProfileCard 派发 `OpenAccountSwitcher`；
  - 新增 `AccountSwitcherDialog` 弹窗构建器：
    - 背景采用半透明遮罩（`this.getTheme().colors.scrim`），点击遮罩或右上角 Close 按钮触发 `CloseAccountSwitcher`；
    - 列表展示当前全部可用账号（通过 `getAccountsList()` 适配 ArkUI `ForEach` 类型系统），并高亮当前选中账号与打勾标识（`✓`）；
    - 点击其他账号派发 `SwitchAccount(accountKey)`，点击当前账号关闭弹窗；
    - 底部提供 `+ Add Account` 按钮，点击派发 `RequestAddAccount`；
    - 严格 100% 遵循 Design Tokens（`T.colors`、`T.typography`、`T.spacing`、`T.radius`），无任何未定义 token；
- `feature/settings/src/main/ets/Index.ets`：
  - 导出全部新增 Intent 与 Effect 类型；
- `feature/settings/src/test/SettingsReducer.test.ets`：
  - 扩充 8 组针对多账号初始默认值、弹窗开关幂等性、切换账号状态与 Effect 产出、添加账号状态与 Effect 产出、账号列表更新的单元测试。

### 2. `entry` 装配与生命周期层
- `entry/src/main/ets/Bootstrap.ets`：
  - `BootstrapResult` 接口扩展暴露 `tdlibParams`、`filesDir` 与 `cacheDir`，便于后续各动态 scope 构建独立 AuthCoordinator；
- `entry/src/main/ets/account/AccountSessionCoordinator.ets` [NEW]：
  - 封装纯领域多账号会话协调器，100% Kit-free；
  - 管理活跃 `AccountScope`、当前 `accountKey` 与订阅监听器；
  - `getAvailableAccounts()`：读取 `AccountRegistry.list()`，按过滤规则产出所有非 closed 账号键名；
  - `switchAccount(key)`：调用 `registry.activate(key)`，切换当前活跃 scope 并通知监听者；支持同账号切换幂等；
  - `addAccount(keyPrefix)`：调用 `registry.create('account_' + Date.now())` 创建新 scope 并通知监听者；
- `entry/src/main/ets/pages/Index.ets`：
  - 保存 `bootstrapResult`、`currentAccountKey`；
  - `aboutToAppear()` 时自 `result.scope` 初始化当前账号并从 `result.registry.list()` 加载账号列表；
  - 接入 `handleSwitchAccount(key)`：
    - 调用 `this.bootstrapResult.registry.activate(key)`；
    - 彻底销毁清理当前旧 scope 的活跃协调器（`chatCoordinator`、`settingsCoordinator`、`searchCoordinator`、`chatListCoordinator`、`coordinator`）；
    - 切换当前 `accountScope` 与 `currentAccountKey`，更新可用账号列表；
    - 为新 scope 构建独立的 `AuthCoordinator` 并启动；
    - 若新账号授权处于 `ready` 态，切至 `home` 并启动 `ChatListCoordinator`；否则切至 `auth` 登录页；
  - 接入 `handleAddAccount()`：
    - 调用 `this.bootstrapResult.registry.create('account_' + Date.now())` 创建新 scope；
    - 销毁旧协调器，切换 `accountScope` 与 `currentAccountKey`；
    - 为新 scope 构建独立的 `AuthCoordinator` 并启动；
    - 将导航栈替换至 `auth` 登录页引导用户输入手机号登录；
  - `openSettings()` 中将 `handleSwitchAccount` 与 `handleAddAccount` 注入 `SettingsCoordinator`；
- `entry/src/test/account/MultiAccountFlow.test.ets` [NEW]：
  - 新增 8 组基于 `FakeAccountBridge` 与 `FakeAppFiles` 的完整多账号流程单元测试：
    1. 初始活跃账号在可用账号列表中的存在性；
    2. 添加账号流程：创建新 scope、切换活跃账号、触发 listener 通知、更新账号列表；
    3. 切换账号流程：切换活跃 scope、触发 listener（isNew=false）、状态一致性；
    4. 切换同账号幂等性：无额外副作用，无重复通知；
    5. 切换不存在账号：优雅返回错误，活跃账号保持不变；
    6. 多账号连续创建与交替切换流程；
    7. 冷启动多账号恢复：从持久化 manifest 恢复多个账号，正确读取列表并激活休眠账号；
    8. 取消订阅功能；
- `entry/src/test/List.test.ets`：
  - 注册并运行 `multiAccountFlowTest()`。
