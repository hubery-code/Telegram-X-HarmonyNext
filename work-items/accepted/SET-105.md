## 实际修改

### 1. 模型：聊字号档位与系统字号正交（core/design_system）

`FontScale.ets` 新增聊字号档位模型：

- `CHAT_FONT_SIZE_STEPS = {12,13,14,15,16,18,20,22,24,26}` —— 逐值对齐 TGX `Settings.CHAT_FONT_SIZES`，默认 15，共 10 档。
- 与既有系统字号 `fontScale`（0.85–2.0 连续、全站生效）**正交**：只作用于消息内容文字。
- 换算取**倍率语义**而非 TGX 的绝对字号：`chatTextSizeOf(base, size, diff) = base × (size/15) + diff`，下限 `MIN_READABLE_FONT_SIZE = 11vp`。

**为什么用倍率而不是绝对字号**：消息文字取自 9 档排版 token（body / subheadline / caption / footnote…）。若改成绝对字号会抹平 token 层级；倍率保留层级关系，且默认档倍率 = 1.0 → **默认视觉与改造前逐像素一致**（实测 15 档控件几何改造前后完全相同）。

### 2. 接线（Theme / ThemeManager / ChatPage）

- `Theme.chatFontSize` + `ThemeManager.setChatFontSize/getChatFontSize` 贯通。
- `feature/chat/ChatPage.ets` 12 处消息内容文字接入，`diff` 偏移对齐 TGX `TGMessage`：正文 `0` / 置顶摘要 `−1` / 副标题 `−2` / 反应 `−4`。

### 3. 设置页（feature/settings，MVI 三层）

- 新增「Chat Text Size」卡片：`ChangeChatFontSize` intent → reducer → coordinator；`Slider` 10 档 + 与聊天页同源的实时预览行。
- `feature/settings/src/main/resources/base/media/ic_text_size.svg` 新增图标。

### 4. 作用域边界（对齐 TGX `timeProvider`）

以下**不缩放**：时间戳 / 日期分隔 / 顶栏 / 输入栏 / 长按菜单 / 空态。依据为 TGX 的 `timeProvider` 使用固定 11sp 且无字号监听器。实测三档下这些控件几何恒定。

### 5. 持久化（entry）

新增 `entry/src/main/ets/store/SettingsStore.ets`（`preferences` Kit）：业务层只写 `AppStorage`、**零 Kit 依赖**，entry 在 `@StorageProp` + `@Watch` 里落盘、启动时读盘回灌 `ThemeManager`。

## 实测中发现并修复的 2 个真实缺陷

### (a) 置顶栏写死 `.height(48)` → 26 档文字向上溢出

- **现象**：栏内两行文字接入字号后，26 档需 ≈58vp，被 `.height(48)` 压回去后**向上溢出 66px**，压到列表首条消息。
- **证据**：`uitest dumpLayout` 显示容器 `[91,363][1116,502]` 而内容伸到 568；自动重叠审计报 2 处相交。
- **修复**：改 `constraintSize({ minHeight: 48 })` + 竖彩条跟随字号。修复后容器 205px 恰好包住两行、重叠归零；15 档几何与改造前一致（`[91,374][1116,492]`）。

### (b) `PersistentStorage.persistProp` 恢复静默失效 → 改用 `preferences` Kit

- **现象**：设置到 26 后落盘文件确实是 `<string key="chatFontSize">26</string>`，但杀进程重启后 `AppStorage.get` 拿到默认 `15`。
- **排除项**：同进程内用 `fileIo` 读同一文件内容仍是 26（文件在、值在、权限够）；`setTimeout(1500ms)` 再读仍是 15（排除异步未落盘）；声明成 `<number>` / `<string>` 结果一致。
- **结论**：该 API 在本 SDK 上读写两端对不上，且**失败静默**。已整体弃用，改走 `preferences` Kit（落盘为 `<double key="chatFontSize" value="26.000000"/>`）。
